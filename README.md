# Напоминалка о дедлайнах

Учебный Telegram-бот. Полное README появится на этапе 9.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Что делает «+1 час / +1 день» | Сдвигает дедлайн; неотправленные напоминания пересоздаются по интервалам пользователя (только будущие) |
| Год не указан в дате | Текущий год; дата раньше сегодняшней уходит на следующий год; время сегодня уже прошло: «Эта дата уже прошла» |
| Двузначный год | `ДД.ММ.ГГ` это `20ГГ` |
| Время `9:05` | Допустимо |
| Несуществующее время (переход на лето) | Ошибка «Такого времени в твоём поясе не бывает»; неоднозначное: первое вхождение (`fold=0`) |
| FSM после перезапуска | Состояние теряется (MemoryStorage) |
| Команда во время диалога | «Сначала закончи диалог или отправь /cancel», состояние сохраняется |
| Список задач | Одно сообщение, до 10 ближайших, внизу «…и ещё N» |
| Кнопки в `/list` | По строке на задачу: `[✅ №N] [🗑 №N]` |
| Просроченная задача | `expired`, одно уведомление с кнопкой «✅ Всё-таки выполнено» |
| Лимит задач | 50 активных на пользователя |
| Отправка напоминания | Сначала отправить, потом `sent=1` (at-least-once) |
| Сводка, `/stats`, `/export` | Не реализуются |
| `DB_PATH`, `LOG_PATH` | Берутся из `.env`, если заданы; иначе значения по умолчанию из ТЗ |
| `requirements.txt` | `APScheduler<4`, чтобы не поставилась ветка 4.x |
| Заглушка `scheduler.py` | Две пустые async-функции до этапа 6 |
| Формат дат в БД | `isoformat(timespec="seconds")` от aware-UTC, доли секунды отбрасываются: единый формат гарантирует корректное сравнение строк |
| `shift_task_deadline` | Работает только с задачами `active`; для `done` и `expired` возвращает `False` (хендлер ответит «Задача не найдена») |
| `expire_overdue_tasks` | Возвращает словари с ключами `task_id`, `user_id`, `title`, `deadline` |
| Поле `reminder_offsets` | `get_or_create_user` отдаёт его строкой `'1440,60'`; разбирает её `utils.parse_offsets` (этап 3) |
| Параметр `tz` в `utils` | Принимает имя пояса (строка IANA) или объект `ZoneInfo` |
| `plural_ru` | Возвращает только слово (`plural_ru(3, "день", "дня", "дней")` даёт «дня»), число подставляет вызывающий код |
| `explain_datetime_error` | Для корректного ввода возвращает пустую строку |
| Время вне диапазона (`25:61`, `24:00`) | Относится к ошибке «Не понял формат»; несуществующий день или месяц: «Такой даты не существует» |
| `29.02` без года | Берётся текущий или следующий год; если в нём нет 29 февраля, ошибка «Такой даты не существует» (следующий високосный год не ищем) |
| Тексты ошибок разбора даты | Лежат в `texts.py` (`ERR_DT_*`), `utils.py` берёт их оттуда |
| Порядок роутеров | `tasks` подключается раньше `start`: общий фильтр «команда посреди диалога» должен сработать до обычных хендлеров команд |
| Команда в любом состоянии FSM (кроме `/cancel`) | «Сначала закончи диалог или отправь /cancel», состояние сохраняется |
| Текст на шаге подтверждения | Напоминание нажать «Сохранить» или «Отмена» |
| Нажатие устаревшей кнопки (состояние не `waiting_confirm`, например после перезапуска) | Всплывающее сообщение «Эта кнопка устарела…», ничего не меняется |
| Дедлайн прошёл, пока пользователь решал, сохранять ли | Задача не сохраняется, пользователю предлагается начать заново |
| Текущее время в хендлерах | Берётся через `tasks._now_utc()`, в тестах подменяется |
| `/cancel` | Не обращается к БД |
| `/list` и `/delete` | Показывают до `LIST_PAGE_SIZE` ближайших активных задач; если их больше, внизу строка «…и ещё N. Заверши или удали часть задач» |
| Активная задача, чей срок прошёл, но job ещё не пометил её `expired` | Показывается в списке с пометкой «просрочено» |
| Чужая и несуществующая задача в кнопках | Одинаковый ответ «Задача не найдена»; `get_task` их не различает, поэтому WARNING пишется для обоих случаев |
| После удаления | Сообщение заменяется на «Удалено 🗑», список не обновляется (нужно снова вызвать `/list`) |
| Кнопка «Нет» при удалении для уже удалённой задачи | «Задача не найдена» |
| Кнопки `✅ №N` в `/list` | Создаются сразу, обработчик `done:<id>` появится на этапе 7 |
